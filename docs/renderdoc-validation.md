# RenderDoc 验证约定

渲染相关变更优先使用 RenderDocMcp。先读取工具返回的工作流指南，按实际 EXE 和配置启动抓帧；已知捕获直接复用，不为形式重复采集。

保留 `.rdc` 与报告，供用户在本地 RenderDoc 打开。产物放在执行仓库的 `artifacts/renderdoc/<阶段>/<场景>/`；独立 VisCore 测试留在 VisCore，产品数据测试留在 MiniCAE。原始 RDC 默认不加入 Git，捕获索引与结论写入 `docs/`。获得用户明确要求后才提交二进制或上传。

每份捕获记录：绝对路径、场景和用途、源代码提交或未提交状态、构建配置、EXE 路径/哈希、GPU/驱动、RenderDoc 版本、关键 eventId、检查项和结果。多个 captures 分别说明用途，不能只给没有上下文的文件。

检查与变更对应的绘制事件、顶点/索引、Uniform、Shader、目标图像、深度和管线状态；必要时使用资源/像素历史或前后帧对比。无视觉基线时明确标记未执行基线判定，不能把工具 completed 自动当作测试通过。

抓帧只观察选中的帧，不能替代 CPU 契约、跨帧生命周期和长期性能测试。工具缺失、API 回放不支持或证据截断时如实记录，并继续可用的验证。CPU-only 或纯文档变更不强制生成无关 RDC。

捕获可能含模型、路径和资源数据，默认保留本地。已有用户捕获不自动清理，生成证据也不在没有明确要求时删除。
